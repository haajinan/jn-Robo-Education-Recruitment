# 基于YOLO模型的饮料罐识别

## 一、课程名称与主要内容

**课程名称**：“从像素到罐子：基于YOLO的饮料罐识别”

**主要内容**：本课程是面向机协成员的AI视觉入门课程，以“饮料罐识别”这一贴近生活的应用场景为载体，带领学员完整走一遍目标检测项目的全流程——数据采集与标注、模型训练、性能评估、边缘部署。课程定位为“入门友好、全流程覆盖”，既适合零AI基础但会一点Python的成员，也为有基础的同学提供模型优化与嵌入式部署的进阶空间。

## 二、课程面向对象及所需基础

**面向对象**：机协大一、大二成员，以及对计算机视觉和嵌入式AI感兴趣的同学。

**所需基础**：

- Python基础语法（变量、循环、函数、类的基本使用）——如果不满足，可在课前安排一次1小时的Python快速回顾；
- 基本的命令行操作能力（`cd`、`pip install`等）；
- 不需要任何深度学习或计算机视觉前置知识，相关概念将在课程中从零讲解；
- 如果涉及边缘部署环节，需要学员对Linux基础操作有初步了解（可在课中穿插讲解）。

**班级规模建议**：12-20人，分为4-5个小组，每组3-4人。分组时注意将有一定编程基础的同学分散到各组，形成“传帮带”效果。

## 三、课程目标

完成本课程后，学员应能够：

1. **理解目标检测的基本原理**：区分分类、检测、分割任务的差异，理解YOLO“单阶段检测”的核心思想——为什么它比两阶段方法（如Faster R-CNN）更适合实时场景。
2. **掌握数据标注与数据集构建**：使用LabelImg等工具对饮料罐图像进行边界框标注，生成YOLO格式的标注文件，并配置`data.yaml`文件。
3. **独立完成YOLO模型的训练与评估**：使用Ultralytics框架，基于自定义数据集微调YOLOv8n模型，读懂训练日志中的loss曲线和mAP指标。
4. **理解模型优化与边缘部署的基本流程**：了解模型量化（FP32→INT8）、剪枝、ONNX导出等技术的作用和效果，能够在Jetson Nano或树莓派上运行训练好的模型进行实时推理。
5. **形成工程化思维**：经历“需求分析→方案设计→数据准备→训练调优→部署验证”的完整工程链条，理解课堂上的AI算法如何落地为可运行的系统。

## 五、数据集方案

这是本课程的关键环节。饮料罐识别面临的实际挑战包括金属表面反光、相似包装设计难以区分、堆叠摆放时的遮挡等，因此数据集的质量直接决定模型效果。建议采用“公开数据集+自采集数据”混合方案：

**方案A：使用公开数据集快速起步。** 可选用包含饮料罐类别的YOLO格式数据集，例如安检X光危险物品识别数据集中包含789个“Cans”标注框，或室内手持饮料罐数据集（94张图像，标注了零度美禄罐、原味百事罐、零度百事罐三个类别）。这些数据集可直接用于教学演示，让学员快速跑通训练流程。

**方案B：自采集数据集（推荐）。** 由学员分组用手机拍摄饮料罐照片，涵盖不同光照条件（日光/室内灯光/逆光）、不同角度（正面/侧面/俯视）、不同背景（桌面/货架/手持）、不同遮挡程度（单罐/多罐堆叠/部分遮挡）。每组采集50-80张，全班汇总后得到约300-500张图像。使用LabelImg标注为YOLO格式的txt文件，类别可设定为`cola_can`、`pepsi_can`、`sprite_can`、`other_can`等3-5类。

**推荐做法**：先用公开数据集让学员快速体验训练流程（第2课时），再用自采集数据做“真正的项目”（第3-4课时），这样既有“快速正反馈”，又有“真实工程体验”。

## 六、教学形式与实践环节

采用 **“讲解演示 + 分组实操 + 成果汇报”** 三位一体的教学形式，借鉴“理论-实验-应用”的教学框架：

- **讲解演示（约30%）**：讲师在Jupyter Notebook上边讲边跑代码，学员同步在自己电脑上操作；
- **分组实操（约55%）**：每组围绕一个子任务（数据标注、训练调参、部署测试）分工协作，讲师和助教巡回答疑；
- **成果汇报（约15%）**：最后一课时各组展示自己的检测demo，汇报训练过程中的发现和遇到的问题。

## 七、课时安排（共6课时，每课时约90分钟）

### 第1课时：目标检测入门与YOLO原理

**理论部分（40分钟）**：

- 从“图像分类”到“目标检测”的思维跃迁：分类回答“是什么”，检测回答“是什么+在哪里”；
- YOLO的核心思想：将检测问题转化为回归问题，一次前向传播同时预测边界框和类别，这是它能达到实时速度的根本原因；
- YOLOv8的架构亮点：无锚框（anchor-free）设计省去了手工设计先验框的繁琐流程，解耦检测头让分类和回归任务各司其职，动态标签分配策略提升了训练稳定性；
- 关键指标解读：mAP（平均精度）、IoU（交并比）、Precision/Recall——这些不是抽象数字，而是判断“模型到底行不行”的依据。

**实践部分（50分钟）**：

- 环境搭建：安装Anaconda、创建虚拟环境、安装`ultralytics`和PyTorch；
- 运行第一个YOLO推理：用预训练的`yolov8n.pt`模型对一张饮料罐图片做推理，观察检测结果的可视化输出；
- 引导学员思考：预训练模型在COCO数据集上见过“bottle”和“cup”类别，但它能准确识别不同品牌的饮料罐吗？如果不能，我们该怎么办？

### 第2课时：数据标注与数据集构建

**理论部分（30分钟）**：

- 目标检测数据集的格式规范：YOLO格式的标注文件长什么样（每行`class_id x_center y_center width height`，归一化到0-1）；
- 数据增强的意义：为什么需要模拟强光、遮挡、旋转等场景？因为这些正是饮料罐识别在实际场景中面临的真实挑战；
- 训练集/验证集/测试集的划分原则。

**实践部分（60分钟）**：

- 安装LabelImg，对准备好的饮料罐图像逐张标注边界框，选择正确的类别标签；
- 将标注导出为YOLO格式的txt文件，编写`data.yaml`配置文件（指定训练/验证路径、类别数和类别名称）；
- 分组交叉检查标注质量：随机抽取10张标注结果互评，发现并纠正漏标、错标、框不准等问题。

### 第3课时：模型训练与调参

**理论部分（25分钟）**：

- 迁移学习为什么有效：COCO数据集上预训练的YOLOv8已经学会了“如何看边缘、纹理、形状”，我们只需要教它“饮料罐长什么样”；
- 训练中的关键超参数：epochs（训练轮数）、batch size（批次大小）、learning rate（学习率）、imgsz（输入图像尺寸）——每个参数改变意味着什么；
- 如何判断模型是否训练好了：观察loss是否收敛、验证集mAP是否停止提升、是否存在过拟合。

**实践部分（65分钟）**：

- 使用`YOLO("yolov8n.pt").train(data="data.yaml", epochs=50, imgsz=640)`启动训练；
- 训练过程中观察实时日志中的`box_loss`、`cls_loss`和`mAP`变化；
- 训练完成后用验证集评估模型性能，可视化混淆矩阵，分析哪些类别容易混淆（比如不同品牌的罐子）；
- 进阶挑战（供有余力的组）：尝试调整`imgsz`为1280，观察小目标检测效果是否提升——多尺度训练（640×640到1280×1280）是应对不同距离饮料罐的有效策略。

### 第4课时：模型评估与优化

**理论部分（25分钟）**：

- 深入理解mAP@0.5和mAP@0.5:0.95的区别；
- 模型优化的三条路径：量化（FP32→INT8，内存占用减少约75%，精度损失不到1% mAP）、剪枝（去掉不重要的卷积核，参数量减少约20%）、TensorRT加速（通过算子融合和层优化获得约1.4倍推理加速）；
- 这些技术不是“炫技”，而是让模型能在算力有限的边缘设备上跑起来的必要手段。

**实践部分（65分钟）**：

- 用训练好的模型对测试集图片做推理，统计各类别的检测准确率；
- 导出模型为ONNX格式（`model.export(format="onnx")`），对比导出前后的推理速度；
- 分析失败案例：找出检测错误的图片（漏检、误检、类别混淆），讨论可能的原因（反光干扰？遮挡严重？训练样本不足？），并提出改进思路。

### 第5课时：边缘部署实战

**理论部分（20分钟）**：

- 边缘计算的意义：为什么不能把所有图像传到云端推理？（延迟、带宽、隐私）；
- 边缘设备的选择权衡：Jetson Nano有128核Maxwell GPU，在TensorRT加速下可实现5.3ms/张的推理速度；树莓派价格更低但CPU-only模式下难以满足实时要求，需要量化优化后才能达到约11 FPS；
- 部署的基本流程：ONNX导出 → TensorRT/TFLite编译 → 在目标设备上运行推理。

**实践部分（70分钟）**：

- 将训练好的模型部署到Jetson Nano或树莓派上（如果设备数量不足，分组轮流操作，其他组在PC上模拟部署流程）；
- 连接USB摄像头，编写一个简单的实时检测脚本：读取摄像头画面 → 推理 → 在画面上绘制边界框和类别标签 → 显示检测结果；
- 观察实际运行中的FPS和检测效果，与PC上的结果做对比，讨论差异的原因。

### 第6课时：成果汇报与总结

- 每组用5-8分钟展示自己的饮料罐检测demo（现场演示或录制视频）；
- 汇报内容包括：数据集规模与构成、训练配置与结果、部署效果、遇到的问题及解决思路；
- 全班讨论：如果要进一步提升性能，下一步可以做什么？（更多数据？更换更大模型？换用YOLOv11？）；
- 讲师总结：从“做一个能跑的项目”到“做一个可靠的系统”之间还差什么。

## 八、可能遇到的问题与解决办法

**问题1：学员编程基础参差不齐，部分学员跟不上实操节奏。**
解决办法：课前发布一份“Python速查清单”（涵盖变量、循环、函数、文件读写等基础内容），让基础薄弱的学员提前自学。实操环节实行分组协作，确保每组至少有1名编程基础较好的成员。助教在教室中巡回，优先帮助进度落后的小组。关键代码提供“填空式模板”——核心逻辑已写好，学员只需修改参数和路径即可运行。

**问题2：环境配置失败（CUDA版本冲突、PyTorch安装错误等）。**
解决办法：这是实操类课程最常见的“翻车点”。建议课前制作一份详细的图文安装指南，并提前在2-3台电脑上验证安装流程。课上如果出现环境问题，先让学员使用Google Colab或AutoDL等云GPU平台作为备用方案——Colab免费提供T4 GPU，运行YOLOv8n训练绰绰有余。同时准备一个预装了完整环境的Docker镜像或conda环境文件（`environment.yml`），供学员一键复现。

**问题3：数据采集质量不理想，模型效果差导致学员挫败。**
解决办法：不要期望300张图片就能训练出生产级模型。课程的目标是“理解流程”而非“做出产品”。讲师需要提前说明：实际工业场景中饮料罐识别系统需要数千张标注图像和多次迭代优化，3米距离下对直径6cm罐子的识别准确率达到92%是需要大量数据和调优的。课程中的模型能达到70-80%的mAP就已经是很好的教学成果。同时，提前准备一套“保底数据集”（可以用公开数据集或往届学员标注好的数据），确保即使自采集数据质量不佳，学员也能看到可用的检测结果。

**问题4：边缘设备数量不足，无法让所有学员同时动手部署。**
解决办法：采用“轮转制”——第5课时分为两个环节，前35分钟第1-2组在Jetson上操作部署，第3-4组在PC上完成ONNX导出和量化实验；后35分钟交换。或者将部署环节作为“演示+跟做”的混合模式：讲师在Jetson上现场演示部署全流程并投屏，学员在PC上同步执行ONNX导出和模型量化步骤，最后分组轮流用Jetson运行推理。

**问题5：课程时间跨度大，学员在第3-4课时之间遗忘前面的内容。**
解决办法：每次课开头用5-10分钟做“快速回顾”，用思维导图梳理上一课时的关键概念和操作步骤。每次课的代码在上一次的基础上累加，形成一条连续的代码演进线（从推理→标注→训练→评估→部署），让学员在代码层面看到自己的“积累”。此外，建立一个课程共享文档或GitHub仓库，学员可以随时回看每节课的代码和笔记。
